# 小屏棋盘点击修复

## 已复现的原因

棋盘原来的拖动阈值是 `8` 个布局单位。布局以 390 宽和至少 700 高缩放，小屏还要扣掉微信胶囊和安全区。例如 320×568、顶部安全区 72 的手机，比例约为 0.709，拖动阈值实际上只有 5.67 个屏幕像素。指尖轻微滑动就会取消点击；默认倍率又不允许平移，因此玩家看起来是“点了没有反应”。

另一个独立原因是按下与抬起必须同时落在**抬起那一帧的同一个精确命中形状**里。小菱形边缘只偏移几像素、信笺浮动或镜头动画重新绘制，都可能让有效按下丢失。

`platform.js` 的原生触摸仍使用窗口坐标；DPR 只放大绘图纹理，`renderer.toLogical` 扣安全区并反算布局比例。检查未发现这条换算链路需要再次乘除 DPR。

## 修复行为

- 棋盘用 **12 个窗口像素**区分点击和拖动，不随手机布局缩小，也不受 DPR 改变。超过阈值后即使手指回到原点也只算拖动。
- 按下时记录画面实际命中的格子。小幅滑动或物件重绘后，抬起仍执行该格子的原有动作。按住期间若缓存的上一步已经执行、状态改变，本次旧触摸取消，防止移动目标变成额外等待。
- 仅完全空白处允许最多 **8 个窗口像素**的边缘容差，并只选择引擎当前允许的相邻格。精确命中的其他格子、远处物件、脚下等待格和指引按钮保持优先；两个目标接近相同时不猜测。
- 依旧通过原有 `selectCell` 和引擎执行动作，首关指引与新道具指引仍可拦截。镜头拖动、双指缩放、取消、退出和重复目标点击保护均保留。

代码：`src/board-input.js`、`src/main.js` 的 `pointerEvent`、`src/scene.js` 的格子动作。

## 自动验证

`node --test tests/small-screen-input.test.js`

该文件覆盖 9 个回归场景，其中矩阵测试实际绘制棋盘并输入按下、7×2 像素滑动、重绘、抬起，共 75 组组合：

| 窗口尺寸 | DPR | 顶部 / 底部安全区 |
| --- | --- | --- |
| 320×568 | 1、2 | 72 / 0 |
| 360×640 | 3 | 76 / 24 |
| 375×667 | 2 | 72 / 0 |
| 390×844 | 3 | 96 / 34 |

每种尺寸分别检查关卡 1、121、301、601、999，镜头倍率 0.65、1、1.4。验证只执行期望的一步、保存路线和引擎重放一致，且轻微滑动不平移镜头。另覆盖菱形边缘、移动中的信笺、真实拖动、墙和远处格子、重复目标、缓存移动中按住、空白边缘容差、微信触摸与 DPR 上限、双指缩放后剩余手指不触发点击。

修复前已运行前两个回归：320×568 上 7×2 像素滑动丢步，格边缘 4×1 像素偏移同样丢步。修复后通过。结果属于自动化窗口/原生 API 模拟，未声称已在实体手机上实测。

整合回归包含 `tests/integration.test.js`、`tests/platform.test.js`、`tests/wechat-devtools.test.js`、`tests/ranking-gestures.test.js`，用于检查邮局屋顶、暴露地砖、动画、首关教学、排名手势等既有行为。关卡及原始难度数据没有修改。
