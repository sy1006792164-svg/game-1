# 游戏体验审查与优化

日期：2026-09-15

## 判断与范围

《风笺回廊》已有移动、等待、三拍回声、顺序收信、风推、纸桥、灯火、驿站与道具，学习内容已较多。本轮围绕现有解谜玩法减少误操作、重复提示和视觉干扰，不再增加新的资源或规则。

审查覆盖首页、选关地图与章节、邮票册、设置、投递、引导、道具、暂停、失败与胜利结算，以及输入、存档、绘制、动效和声音模块。项目没有业务后端；平台能力沿用现有微信接口。

## 已落实

| 问题 | 调整 |
| --- | --- |
| 长按时提示框增高，棋盘在手指下重新排布 | 棋盘始终使用普通提示的布局；预览临时替换道具区内容，保留原占位，松手恢复且不耗拍 |
| 长按的方向箭头始终朝右，虚线路径失效 | 箭头跟随等距投影方向；预览虚线保留风推拐点 |
| 收齐信笺的阶段提示遮住蓝票预告 | 蓝票未齐时持续显示回声时间线，收集结果由原目标栏反馈 |
| 顺序收信文案盖过当前紧急提示 | 优先显示堵路、邮局缺件、下一拍盖票和低灯火信息 |
| 交互型机关提示吞连续输入、阻止查看补给 | 统一交互限制；允许一次正常输入缓存，允许打开已可用道具 |
| 道具栏展示未解锁工具、无桥关的修桥包 | 按解锁状态和本关配置展示；关内不因目标变化重排按钮 |
| 同格收集叠加普通落脚光圈与粒子 | 仅去除已被收集特效覆盖的重复落脚装饰，保留其他反馈 |
| 普通选关直接覆盖正在进行的路线 | 有实际进度或已领取补给时先展示原路线计划；取消保持存档，确认后切换；兼容旧快照存档 |
| 通关后无法直接离开，重复教程增加卡片高度 | 统一为下一封、再走一次、返回邮局；删除重复教程和收藏按钮，保留领奖演出及首页收藏入口 |
| 极小屏的长弹窗可能裁掉底部操作 | 使用实际触控高度预算紧凑间距和分页，保留字号、点击范围与边距 |

## 验证范围

- `npm test`：779 项全部通过；`npm run build`、`npm run check` 和 `git diff --check` 通过。
- 使用实际浏览器游戏和正式美术图集，检查首页、地图、章节、邮票册、设置、邮程及投递界面。
- 检查 320×568 小屏和 240×480 窄屏；实际完成长按等待预览、松手不耗拍、四步投递、回声收票、三星结算和返回首页。
- 关卡校验覆盖全部 999 关，原始路线均可无道具、无续灯三星通关；未改变关卡、评分或奖励规则。
- 回归用例扩展在原有测试文件内，没有新增临时测试文件或运行时模拟数据。
- 微信真机、真实广告、好友排行授权和实际上传包体未在浏览器中验收。

## 后续可单独评估

静态背景仍按现有帧率绘制。进一步缓存应先测量真机内存和耗电；本轮没有直接降低主循环频率，因为长按判定、结算与短时反馈也依赖主循环。现有音频声部上限、优先级、音量避让及释放机制继续复用。
